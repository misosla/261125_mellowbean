# 웹디자인 규칙

사용자가 같은 수정 요청을 반복하지 않도록, 대화에서 파악한 규칙을 모아 둔 문서다.

## 쓰는 법

1. 프로젝트 폴더에 `디자인노트.md`가 있으면 먼저 읽는다. 색, 글꼴, 하지 않을 것은 그 문서가 기준이다.
2. 아래 **확정 규칙**은 요청받지 않아도 처음부터 적용한다.
3. **후보**는 아직 한 번만 나온 의견이다. 자동으로 적용하지 않되, 어느 쪽이든 괜찮은 선택이라면 후보를 따른다.
4. 이번 대화의 지시 > `디자인노트.md` > 확정 규칙 > 후보 순으로 따른다.
5. 작업을 마치기 전에 확정 규칙을 하나씩 대조해 확인한다.

## 확정 규칙

### 파일과 이미지
- 폴더와 파일 이름은 영문으로 짓는다. 파일은 소문자와 하이픈을 쓰고 용도를 앞에 붙인다. 예: `menu-cafe-latte.jpg` (2026-11-25)
- 사진은 직접 열어 내용을 확인한 뒤 이름을 짓는다. (2026-11-25)
- 웹용 이미지는 적합한 크기로 줄이고, 원본은 별도 폴더에 그대로 보존한다. (2026-11-25)

### 설명 방식
- 사용자는 웹디자인이 처음이다. 전문 용어는 쉬운 말로 풀고, 후보마다 느낌을 한 줄로 설명한다. (2026-11-25)
- 결정은 사용자가 한다. 비교와 추천은 하되 대신 정하지 않는다. (2026-11-25)

## 후보

- 글자를 너무 작게 하지 않는다. 사용자가 반복될 수 있는 예로 들었다. (2026-11-25, 1회)
- 글자를 너무 가늘게 하지 않는다. 사용자가 반복될 수 있는 예로 들었다. (2026-11-25, 1회)
- 디자인을 정한 뒤에는 말로만 설명하지 말고 미리보기 이미지도 보여준다. (2026-11-25, 1회)
- 카페 사이트에 흔한 크림색 + 갈색 조합은 제안하지 않는다. (2026-11-25, 1회)
